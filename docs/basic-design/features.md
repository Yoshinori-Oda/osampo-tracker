# 機能一覧

基本設計書の2本目。アプリ・バックエンドが提供する機能を一覧にする。2026-10-15時点のmainの実装を正とし、
未実装の機能は「予定」の節に分ける。予定の日程・進み具合は`docs/plans/user-feature-plan.md`の「作業の洗い出し」と
`docs/plans/roadmap.md`で管理し、ここには書かない。

画面ごとの細かい挙動は`docs/design/screens.md`ほか、APIの仕様は`backend/docs/API設計ドラフト.md`を参照。

## 利用者

| 利用者 | 説明 |
|---|---|
| ユーザー | アプリにサインアップしたユーザー(ロール`user`)。自分の記録だけを扱える |
| 管理者 | ロール`admin`のユーザー。同期APIで他のユーザーのデータも扱える。管理者向けの画面は無い |
| 運用者 | バックエンドを動かす開発者。管理用のコマンド(CLI)でユーザーを操作する |
| システム | worker(定期実行)・アプリの自動処理 |

## 実装済みの機能

### 収録(F-REC)

| ID | 機能 | 概要 | 実行者 | 画面・実装 |
|---|---|---|---|---|
| F-REC-01 | 現在地の表示 | 地図(OpenStreetMap)に現在地を表示する | ユーザー | 収録タブ(`recording_page`) |
| F-REC-02 | 位置情報の状態の表示 | 権限が無い・未取得・更新停止・精度低下を、全タブ共通のバナーで知らせる。GPSを掴むためのTipsのページへのリンク付き | システム | `location_banner_view`、`gps_help_page` |
| F-REC-03 | 収録の開始 | 現在地を取得してから収録を始める。取得できなければ、15秒以内に確認できた位置で始めるかを聞くか、開始を止める | ユーザー | 収録タブ |
| F-REC-04 | 位置情報の記録 | 収録中は5秒ごとに位置情報の点(緯度・経度・高度・精度など)を端末に記録し、距離・時間・獲得標高を集計する | システム | `tracking_service` |
| F-REC-05 | バックグラウンドでの収録 | アプリがバックグラウンドに回っても収録を続ける(Androidは常駐通知付き) | システム | `docs/design/background-recording.md` |
| F-REC-06 | 収録の停止と保存/破棄 | 停止すると保存/破棄の画面を出し、名前・移動手段を付けて保存するか破棄する | ユーザー | `save_or_discard_page` |
| F-REC-07 | 権限を失ったときの強制停止 | 収録中に位置情報の権限・サービスが無くなったら収録を止め、保存/破棄を確認する | システム | `docs/design/location-tracking.md` |
| F-REC-08 | 未完了の収録の回収 | アプリが強制終了して保存/破棄されずに残った収録を、次の起動時に保存/破棄させる | システム | `docs/design/session-recovery.md` |

### 記録の閲覧・編集(F-HIS)

| ID | 機能 | 概要 | 実行者 | 画面・実装 |
|---|---|---|---|---|
| F-HIS-01 | 記録の一覧 | 保存した記録(セッション)を一覧にする | ユーザー | 履歴タブ(`saved_sessions`) |
| F-HIS-02 | 記録の詳細 | 地図上の軌跡(ルートの線/全ての点のピン)、移動距離・移動時間・平均速度・獲得標高・最高/最低高度、高度のグラフを表示する | ユーザー | `session_detail_view` |
| F-HIS-03 | 記録の編集 | 名前と移動手段(徒歩・ランニング・自転車・車・電車・飛行機・船)を変える | ユーザー | 履歴タブの編集モード |
| F-HIS-04 | 記録の削除 | 確認のうえで記録を削除する | ユーザー | 履歴タブの編集モード |
| F-HIS-05 | お気に入り | 一覧の☆で記録をお気に入りにする・外す(同期の対象) | ユーザー | 履歴タブ |

### 統計(F-STA)

| ID | 機能 | 概要 | 実行者 | 画面・実装 |
|---|---|---|---|---|
| F-STA-01 | 期間ごとのグラフ | 月・年・全期間を切り替えて、距離か時間をグラフにする(月・年は棒グラフ、全期間は累積の折れ線)。日曜・祝日は色を変える | ユーザー | 統計タブ(`analytics_page`) |
| F-STA-02 | サマリー | 選んだ期間の合計距離・合計時間・回数など。徒歩・ランニング・自転車の距離は別に集計する | ユーザー | 統計タブ |
| F-STA-03 | 自己ベスト | 最長距離・最長時間・最大の獲得標高・最高/最低高度 | ユーザー | 統計タブ |

### 同期(F-SYN)

| ID | 機能 | 概要 | 実行者 | 画面・実装 |
|---|---|---|---|---|
| F-SYN-01 | 記録の同期 | 未同期の記録の登録・更新・削除をサーバーへ送り(push)、他の端末での変更を取り込む(pull)。保存・編集・削除の直後、起動時、フォアグラウンドへの復帰時に行い、失敗したら5分後に再試行する | システム | `tracking_repository`、`docs/design/sync.md` |
| F-SYN-02 | 削除と編集の競合の解決 | 他の端末で削除された記録をこの端末で編集していた場合、削除を受け入れるか、編集内容を残して復活させるかを選ばせる | ユーザー | `delete_conflict_dialog` |
| F-SYN-03 | 削除の突き合わせ | 長く同期していなかった端末では、サーバーに無くなった記録をidで突き合わせて消す | システム | `docs/design/sync.md` |

同期はメールアドレスの確認が済んだユーザーだけが行える。未確認の間や、通信できない・トークンが切れている間も、収録・閲覧・編集は端末だけでできる。

### アカウント・認証(F-ACC)

| ID | 機能 | 概要 | 実行者 | 画面・実装 |
|---|---|---|---|---|
| F-ACC-01 | 新規登録 | メールアドレス・パスワード(8〜128文字)・表示名で登録し、確認コードのメールを送る | ユーザー | `signup_page`、`POST /api/auth/signup` |
| F-ACC-02 | ログイン | メールアドレスとパスワードでログインする。未ログインのまま起動するとログイン画面を出す | ユーザー | `login_page`、`AuthGate` |
| F-ACC-03 | ログイン状態の維持 | トークンを端末に保存して起動時に復元する。アクセストークンが切れたら自動で更新する | システム | `auth_service`、`authorized_client` |
| F-ACC-04 | メールアドレスの確認 | メールで届いた6桁のコードを入力して確認する。コードの再発行(60秒あけて1日5回まで) | ユーザー | `email_verification_page` |
| F-ACC-05 | 認証の状態の表示 | 再ログインが必要なとき・メールアドレスが未確認のときにバナーを出し、タップで該当の画面を開く | システム | `auth_banner_view` |
| F-ACC-06 | 表示名の変更 | 1〜50文字 | ユーザー | 設定タブ(`settings_page`) |
| F-ACC-07 | パスワードの変更 | 現在のパスワードで確認して変える。他の端末のログイン状態を無効にし、変更を知らせるメールを送る | ユーザー | `change_password_page` |
| F-ACC-08 | ログアウト | ログアウトの前に同期を試み、失敗したら警告する。収録中はできない | ユーザー | 設定タブ |
| F-ACC-09 | アカウントの削除 | 確認のうえで、アカウントと関連するデータをサーバーとこの端末から物理削除する。収録中はできない | ユーザー | 設定タブ、`DELETE /api/users/me` |

端末のデータはログインしたユーザーごとに分けて持つ。別のユーザーでログインしても、前のユーザーの記録は見えない。

### 運用(F-OPS)

| ID | 機能 | 概要 | 実行者 | 実装 |
|---|---|---|---|---|
| F-OPS-01 | メールの送信 | outboxに積まれたメールを5秒ごとにSMTPで送る。失敗したら再試行する(1通あたり5回まで) | システム | worker |
| F-OPS-02 | 期限切れデータのパージ | 削除から90日を過ぎた記録のtombstone、期限切れのリフレッシュトークン・無効にしたログイン状態、90日を過ぎたメールの送信記録を物理削除する(24時間ごと) | システム | worker |
| F-OPS-03 | アカウントの停止・解除 | 指定したメールアドレスのアカウントを停止・解除する | 運用者 | `python -m app.cli disable-user` / `enable-user` |
| F-OPS-04 | 開発用データの投入 | 管理者・テストユーザー・メールアドレスが未確認のユーザーを入れる | 運用者 | `python -m app.cli seed-dev` |
| F-OPS-05 | テストメールの送信 | テストメールをoutboxに積む | 運用者 | `python -m app.cli send-test-mail` |
| F-OPS-06 | ヘルスチェック | apiが動いているかを返す(composeのhealthcheckが使う) | システム | `GET /health` |

## 予定の機能

| 機能 | 概要 |
|---|---|
| パスワードのリセット | パスワードを忘れたときに、メールのコードで確認して再設定する |
| メールアドレスの変更 | 新しいアドレスに確認コードを送って変える |
| ローカルアカウント | 同期しないアカウント。作成・切り替え、通常のアカウントとの相互の変更 |
| 行レベルセキュリティ(RLS) | 本人のデータだけを扱える制限を、アプリ層に加えてDBでもかける |
| 管理者の機能 | 招待の発行、ユーザーの一覧、アカウントの無効化(設定タブの中で、管理者のときだけ出す) |
| 設定タブの残り | パスワードのリセットへの導線、メールアドレスの変更 |
| このアプリについて | ライセンス・プライバシーポリシー等 |
| 監査ログ | ログインの成功・失敗、招待、パスワードの変更、管理者の操作を記録する |
| ログインの試行回数の制限 | 監査ログの失敗の記録を使ってロックする |
| 端末の管理 | 端末の一覧、端末ごとのログアウト |
| 外部サービスでのログイン(OAuth) | Google等のアカウントでログインする。自前の認証を作った後に対応させる |

## 採用しない機能

| 機能 | 理由 |
|---|---|
| Firebase Auth等の認証基盤のサービス | 仕組みを理解するため認証は自前で実装する。自前の実装の後に比較する程度に留める |
| QRコードの読み取り | 本案件の要件に寄りすぎていて、このアプリでの使い道に無理がある |
| SNS的な機能(自己紹介・フォロー) | 表示名だけを持つ |
| サーバーからのリアルタイムのpush通知による同期 | 複数の端末での同時操作を想定しない規模では、投資対効果が薄い |
