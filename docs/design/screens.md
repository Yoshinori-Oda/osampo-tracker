# 画面・UI部品の仕様メモ

`frontend/lib/views/`・`widgets/`・`utils/`の個別の仕様。収録・保存/破棄の流れに関わるものは
`docs/design/location-tracking.md`・`docs/design/session-recovery.md`を参照。

## views/

- saved_sessions.dart: 保存済みセッション一覧。編集モード中にListTileをタップすると名前・移動手段を
  編集するダイアログを表示する。名前欄は空欄でsubmitされた場合は変更しない。移動手段は
  `DropdownButtonFormField<MoveMethod>`で選択する
- gps_help_page.dart: GPSを掴みやすくするためのTipsページ。「未取得/更新停止」の位置情報バナーと
  `startRecording`のブロックダイアログの両方から`widgets/gps_help_link.dart`経由でリンクしている
- save_or_discard_page.dart: 収録停止後の保存/破棄画面。session_detail_view.dartの
  `SessionDetailTitle`/`SessionDetailBody`を流用して詳細画面と同じ見た目にしている
  (詳細: `docs/design/session-recovery.md`の「保存/破棄画面」)
- settings_page.dart: 設定タブ(2026-10-14に設計)。今はアカウントの欄のみ(「このアプリについて」(ライセンス・プライバシーポリシー等)は
  仕上げで作る。アカウントとアプリの操作の設定を別のタブに分ける再構成は将来。`tasks`ブランチの`task_candidates.md`)
  - 並び: 表示名(タップで編集ダイアログ。1〜50文字) → メールアドレスと確認状態(未確認ならタップで確認コードの入力画面) →
    パスワードの変更 → ログアウト。アカウントの削除は取り返しのつかない操作なので、区切って一番下に置く
  - 収録中は、ログアウト・アカウントの削除はできない(スナックバーで止める)。表示名の編集・確認コードの入力・パスワードの変更は
    収録に影響しないのでできる
- auth/change_password_page.dart: パスワードの変更画面(設定タブから開く)
  - 入力欄は「現在のパスワード」「新しいパスワード(8〜128文字)」「新しいパスワード(確認)」。「パスワードを表示する」で3つとも見えるようにできる
  - 端末で確かめること: 未入力、新しいパスワードの長さ、確認との一致(満たさなければ送らない)
  - 現在のパスワードが違う(400 `invalid_current_password`)ときは、その欄の下に「現在のパスワードが違います」と出す
  - 成功したら、スナックバーで「パスワードを変更しました。他の端末はログインし直しになります」と出して閉じる(この端末はログインしたまま)
- auth/email_verification_page.dart: メールアドレスの確認コード(6桁)の入力画面(2026-10-14に設計。APIとのやり取り・
  状態の更新は`frontend/docs/ユーザー機能追加に伴う変更予定.md`の「メールアドレスの確認」)
  - 入り口は3つ: サインアップの直後(自動で開く)、未確認のバナーのタップ、設定タブの確認状態の行のタップ。
    収録中でも開ける(同期の再開が収録を邪魔しないため)
  - 表示: 送り先のメールアドレスと「届いた6桁のコードを入力してください」。サインアップの直後に開いたときだけ「あとで」ボタンを出し、
    押すとメイン画面へ進む(未確認でも記録はできる。後からバナー・設定タブで開ける)。それ以外の入り口ではAppBarの戻るで閉じる
  - 入力欄: 数字のみ・6桁まで(数字キーボード、iOSのワンタイムコードの自動入力に対応)。6桁そろうまで「確認」ボタンは押せない。
    6桁そろっても自動では送らない(打ち間違いで入力の失敗の枠(5回)を減らさないため)
  - 「コードを再発行」ボタン: 画面を開いただけでは送らない(サインアップ時に送り済みで、二重に送ると1日5回の枠も減るため)。
    押せるようになるまでの秒数をボタンに表示し、その間は押せない。サインアップの直後は60秒から始める。待ち時間は画面の中だけで持ち、
    閉じて開き直すと押せる状態に戻る(早すぎる再発行はサーバーが429で止めるので、その秒数から数え直す)
  - エラーの表示:

    | 応答 | 表示 |
    |---|---|
    | `invalid_verification_code` | 入力欄の下に「コードが違います」 |
    | `verification_code_expired` | 「有効期限が切れたか、入力の回数の上限に達しました。コードを再発行してください」 |
    | 再発行で409(`email_already_verified`) | 確認済みとして扱い、ユーザー情報を取り直して閉じる |
    | 429(`too_many_requests`) | 「再発行には時間をあけてください」と出し、`Retry-After`の秒数からカウントダウンを始める(残りの秒数は再発行のボタンにだけ出す。2026-10-14にシミュレータで確認して変更) |
    | 通信できない | 「通信できませんでした」(入力内容は残す) |

  - 確認に成功したら、画面を閉じてスナックバーで「メールアドレスを確認しました」と出す

## widgets/

- location_banner_view.dart / recording_phase_banner_view.dart: 全タブ共通で`main_page.dart`の
  `body`上部に表示するバナー
- auth_banner_view.dart: 同じく全タブ共通のバナー。再ログインが必要なとき(タップでログイン画面)と、メールアドレスが未確認のとき
  (タップで確認コードの入力画面)に出す
- gps_help_link.dart: gps_help_pageへのリンク

## utils/

- save_or_discard_screen.dart: 保存/破棄画面を表示する`showSaveOrDiscardScreen()`。通常の停止/
  権限エラーによる強制停止/起動時リカバリのすべてから`TrackingService`経由で使う共通の入口
- duration_format.dart: 経過時間/時刻表示の共通フォーマッタ
